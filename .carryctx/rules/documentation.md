# Documentation rules

Use canonical HTTPS URLs in README and AGENTS files. Keep workspace identity
descriptors consistent with the roster. Keep organization governance here and
canonical product design in koma-docs and implementation claims in their owning
product repository. Read upstream Phodopus
guidance without rewriting its identity or ownership.

Use clear status words: implemented, compiled, runtime observed, independently
accepted, planned, or blocked. Preserve useful architecture documents but do not
present a design target as a tested guarantee. Include versions and exact
commands in evidence. Avoid hardcoded workstation paths except the agreed
disposable `/tmp/koma/` convention; discover ISOs through `ISO_PATH`.
