# Organization repository guidance

This repository owns the [komawm organization profile](https://github.com/komawm) and the [workspace setup kit](https://github.com/komawm/.github/tree/main/workspace). Product behavior and runtime tests belong to [Koma](https://github.com/komawm/koma) and [Jiku](https://github.com/komawm/jiku), canonical specifications to [koma-docs](https://github.com/komawm/docs), Lua types to [koma-types](https://github.com/komawm/koma-types), and distribution/CD work to [packaging](https://github.com/komawm/packaging). Read the [workspace policy](https://github.com/komawm/.github/blob/main/workspace/AGENTS.md) before cross-repository work.

Run commands inside their owning repository. Use CarryCtx here for organization and workspace tasks; this checkout has its own database, agent identities, sessions, and task prefix. Record scope, decisions, checkpoints, and acceptance evidence before ending a session. Initialize state separately in a fresh clone; never commit databases or push raw CarryCtx snapshots.

Read the [CarryCtx delivery rules](https://github.com/komawm/.github/blob/main/.carryctx/rules/delivery.md) and [local-to-release workflow](https://github.com/komawm/.github/blob/main/.carryctx/workflows/local-to-release.md). The six `komawm` repositories are published on GitHub (`remote_changes_enabled = true`) and configured from the [declarative plan](https://github.com/komawm/.github/tree/main/github). Koma uses `v0.0.x` incubation versions until independent `v0.1.0` product release acceptance. Under ignored `recording/`, `recording/references/` holds read-only external reference clones (such as `Hyprland` and `niri`) alongside VM images and local acceptance evidence. CodeRabbit review conventions are prepared for the bot the user will install; missing remote service access must not block local infrastructure acceptance.

Maintain the root templates as the source of truth. Deploy them using the bootstrap script, which refuses conflicts. Keep the workspace roster and repository descriptors consistent. Keep documentation links as canonical HTTPS URLs so each repository remains understandable independently. Do not use workstation-specific absolute paths in public documentation.

Repository guidance overrides shared contribution defaults. Docs (local `koma-docs`, remote `komawm/docs`) is MIT documentation with local Markdown checks and no CI/CD, issue/PR, required review, or CodeRabbit requirement. Packaging is MIT distribution/CD infrastructure with local checks and no generic CI or issue/PR requirement; accepted artifacts can be published to the corresponding Koma/Jiku GitHub Releases when authorized. Koma and Jiku use GPL-3.0-or-later; koma-types uses Apache-2.0. Each owned repository has one root `LICENSE`.

Run `just check` for template, Python, Markdown-link, metadata, and Actions validation. Run `just workspace-check` only from a checkout with its sibling repositories installed. Changes to file installation logic also require temporary-directory probes for idempotence, conflicting destinations, and symlink refusal. Do not change product source, publish repositories, or install desktop sessions as part of workspace maintenance.

Use `just hooks-install` to compose lefthook with managed CarryCtx hooks. Do not bypass hooks. Dependabot handles GitHub Actions here; the Rust product repository handles Cargo dependency updates and explicitly reviewed Rust toolchain pin updates separately.
